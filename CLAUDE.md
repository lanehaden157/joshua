# Joshua

@biblecore/BOOK_CLAUDE.md

Above = shared guide (commands, files, chat side, threads). Below = what
Joshua does differently; it wins.

- `python tools/build_english.py`: `Joshua-english.txt` from the WEB USFM
  (Joshua-only). Provenance only, never the base of the translation.
- Synced extras (`book.json` `sync.extra`): `Joshua-reading.txt`,
  `Joshua-english.txt`, `candidate-boundaries.md`.
- `source-artifacts/` is current for every built unit: edit there and re-port,
  don't edit `units/` by hand. Re-porting a built unit needs `--force`; check
  the source artifact is the current one first, or local roots are lost.
- Retrofit, one source word as two English spans: keep the span a reader
  recognises as the word and `unwrap` the other. Demoting to `rl` isn't
  enough: it still picks up the root's colour.
- `data/palette.json` runs short → expand by generation, not by eye.

## Corpus

Pins: morphhb 2.0.2 (`package.json`; `npm ci` restores it), HebrewLexicon @
`21c9add` (`corpus/lexicon/`), WEB classic USFM (`corpus/web/`).

Checked against printed BHS: 658 verses (chapter 21 has 45; 21:36–37 present,
unmarked), 10,083 words (10,051 running text + 32 Qere rows), 52 petuḥah + 42
setumah = 94 breaks. Count drifts on re-fetch → flag loudly.

Generated by `corpus`, don't edit: `Joshua-reading.txt`, `Joshua-words.tsv`,
`candidate-boundaries.md`. They carry native Hebrew as reference data: never
copy it into chat or a fragment; transliterate. Transliteration is core's;
bible-core's `tests/test_hebrew.py` is the authoritative definition.
